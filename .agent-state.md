## Critical Decisions & Context
- Multi-tenancy model: Shared DB + Schema with `organization_id` foreign keys + Supabase RLS.
- Settings & Role Security: All team role modifications, member removals, and org profile edits are role-gated server-side (only `owner` or `admin`). Last owner removal or demotion is blocked.
- Reusable Project Templates: `project_templates` and `project_template_tasks` schema with day-offsets, default deliverables, and automatic task/deliverable scaffolding upon project instantiation.
- Client Communication Mode: Clients support `manual` and `connected` modes. Strict one-way promotion (`manual` -> `connected`) is enforced permanently. In `connected` mode, webhook ingestion auto-matches messages by email/phone into unified inbox; in `manual` mode, incoming messages are never auto-matched and communication views show only manual records.
- AI Feature Architecture: Provider-agnostic shared layer (`lib/ai/client.ts`) supporting OpenAI, Anthropic Claude, Google Gemini, and a deterministic Mock provider. Dual-gating enforced via Super Admin kill switch (`platform_settings.global_feature_flags.ai_kill_switch`) and tenant subscription plan limits (`subscription_plans.feature_limits.ai_features_enabled`). Centralized prompt templates in `lib/ai/prompts/` and per-tenant usage accounting in `ai_usage_log`.
- AI Inbox Reply Suggestions: Context-aware suggestions analyzing up to 6 recent thread messages into 3 tone options (Professional, Collaborative, Direct/Concise). Strictly human-in-the-loop (never auto-sends). Mode-aware: connected mode offers 1-click send via channel or edit in draft; manual mode offers draft editing and clipboard copy. Dual-tier gating enforced: AI-disabled organizations render no button at all.
- AI Lead Scoring in CRM Pipeline: Deal cards in `/leads` and `/clients/[id]/pipeline` display an objective 0–100 AI Score badge with color coding (0–33 Red: Low Quality, 34–66 Yellow: Medium Potential, 67–100 Green: High-Quality Prospect). Evaluates 4 dimensions: Deal Value, Stage Progression Velocity, Client Engagement (from `communication_messages`), and Project History (completed vs overdue from `projects`). Clicking the badge opens `LeadScoreBreakdownModal` with a circular score gauge, executive rationale, factor impact cards, recommended action, and on-demand re-score. Header includes 1-click batch re-score. Strict dual-tier gating omits all score badges and buttons when AI is disabled. Lead scores are assistive signals only and never automatically transition pipeline stages. All scoring requests are accounted in `ai_usage_log`.
- AI Auto-Task Extraction from Messages: Interactive task extraction available on message threads in `/inbox` and `/clients/[id]/communications`. Evaluates message content for actionable requests, deliverables, and deadlines, extracting candidate tasks with title, context description, calculated due date, suggested assignee role, and confidence score (0–100%). Strictly human-in-the-loop: candidate tasks are presented in `TaskExtractionModal` via `SuggestedTaskCard`, allowing project selection (pre-selecting the client's active project) and assignee configuration prior to creation. Tasks are never auto-created silently. Creation inserts rows into `public.tasks`, attributes source snippet context, and logs `TASK_CREATED` audit events. Dual-tier gating enforced (platform kill switch + plan limit): zero-button rule applied when disabled. All invocations logged in `ai_usage_log`.
- AI Weekly Report Narratives: Pure feature orchestrator `generateWeeklyReportNarrative` synthesizing 6 business metrics (completed tasks, active projects, new clients, revenue, communication volume, overdue items) into an executive Markdown narrative report. Strict anti-fabrication prompt ensures 100% metric fidelity with zero invented numbers. "Generate Weekly Report" action available on `/dashboard` and dedicated `/reports` page. Provides `WeeklyReportModal` with 6 metric badges, inline Markdown editing, print/PDF export styling, and stakeholder email sharing. Zero-button rule enforced when AI is disabled. Pluggable for automated n8n/Slack cron (Task 52) and Analytics (Task 58). All invocations recorded in `ai_usage_log`.
- AI Settings & Usage Controls: Per-organization AI feature toggles stored in `organizations.ai_feature_settings` (JSONB) with full tenant administration. Enforces three-tier gating hierarchy: (1) Platform kill switch & feature flags (`platform_settings`), (2) Subscription tier plan limits (`subscription_plans.feature_limits`), (3) Organization-level feature toggles. Tenant admins and owners can toggle 4 independent capabilities: `reply_suggestions`, `lead_scoring`, `task_extraction`, and `weekly_narrative`. Dedicated UI at `/settings/ai` surfaces live monthly consumption metrics (total requests, token volume, estimated cost) aggregated from `ai_usage_log`, alongside granular capability cards with active/disabled badges and switch controls. All configuration changes log `AI_FEATURE_TOGGLE_UPDATED` audit events.
- N8N Automation Architecture & Webhook Contracts: Defined event contract and signed outbound webhook sender (`lib/automation/emitter.ts`) for the self-hosted n8n instance on Contabo VPS (`n8n.innoventixhub.com`). Tenant organizations configure `automation_webhook_url` and `automation_webhook_secret` (Migration `0024_organization_automation_webhooks.sql`) with environment fallback. All payloads (`project.delivered`, `task.deadline_approaching`, `project.overdue`, `weekly.summary_ready`) are signed via HMAC-SHA256 (`X-Automation-Signature: sha256=<hex>`), including unique delivery ID and ISO timestamp. Inbound verification route available at `/api/automation/events`. Full architecture and n8n Code node verification scripts documented in `documentation/automation-contracts.md`.
- Automation: Project Delivered -> Invoice Trigger: Implemented N8N Flow 1 connecting Project Management to Invoice Automation. On project status transition to `delivered`, server action evaluates client billing schedule (`payment_schedule === 'per_project'`). If per-project, updates `delivered_at`, flags `invoice_triggered = true`, emits signed `project.delivered` event, and logs `PROJECT_DELIVERED_INVOICE_TRIGGERED`. Confirmed callback route at `/api/automation/callback/invoice-created` validates HMAC signature, updates status to `invoiced`, and logs audit trail. UI integration delivers `DeliverProjectConfirmModal` in both project detail header (`ProjectHeader.tsx`) and Kanban board (`ProjectsKanban.tsx`). Full workflow export provided in `n8n/workflows/project-delivered-invoice.json`.
- Automation: Deadline & Overdue Alerts: Implemented N8N Flow 2 (Task Due Tomorrow Alert) and Flow 3 (Project Overdue Alert) triggered via daily cron route at `/api/automation/cron/deadline-check`. Scoped per organization with secret-header protection (`x-cron-secret` / `Authorization: Bearer`). Idempotent deduplication query checks `in_app_notifications` to prevent duplicate daily alert dispatch for identical entities. Emits signed `task.deadline_approaching` and `project.overdue` events to n8n and stores in-app notifications. Complete n8n workflows provided in `n8n/workflows/task-deadline-alert.json` and `n8n/workflows/project-overdue-alert.json`.
- Automation: Weekly Summary Report: Implemented N8N Flow 4 scheduled for Monday 9:00 AM via cron route `/api/automation/cron/weekly-summary`. Aggregates 6 key multi-tenant operational figures: completed tasks, active projects, new clients, delivered/invoiced revenue, communication message volume, and overdue items across the trailing 7 days. If AI narrative capability is permitted by the 3-tier gating check (`checkAIAccess`), generates an executive narrative via `generateWeeklyReportNarrative`; otherwise cleanly omits the narrative while preserving metric integrity. Emits signed `weekly.summary_ready` event to n8n for Slack distribution to `#leadership` and writes in-app notification record. Full workflow export provided in `n8n/workflows/weekly-summary.json`.
