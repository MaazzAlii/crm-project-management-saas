# 01 - Audit the existing code (no changes)

Read the project and report back. Do not change any files.

1. List the folder structure of `app/`, `lib/`, `components/`, and any existing sales, deals, clients, or CRM modules.
2. Find the existing database schema and migration system. Show how tables are created and how migrations run on startup.
3. Find the existing auth helpers: how the current user, organization ID, and role are read on the server.
4. Find how existing list pages, forms, modals, and API routes are built. Note the pattern for data fetching (server components, route handlers, or server actions).
5. Find the existing clients table and any sales or deals code. Note what already exists and what is missing.
6. List the UI components and styles in use (Tailwind config, color tokens, button and card styles).
7. Write `docs/pipeline-plan.md` with: current structure, the reuse plan, the list of new files you expect to create, and any risks or conflicts.

Stop after writing the plan and summarize it in under 15 lines.
